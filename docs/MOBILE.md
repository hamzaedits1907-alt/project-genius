# Genius for Android and iOS

The phone apps are the **same signed-in web app** (Genius Web) packaged with [Capacitor](https://capacitorjs.com): same account, same synced conversations, same Chat / Research / Code assistant / Agent Mode (web tools), same settings. The app screen is bundled inside the app (`dist-mobile`), so it starts instantly; the web functions (`/api/web`, `/api/relay`) are called at `https://project-genius.netlify.app` (override with `VITE_API_BASE`).

| What | Where |
|---|---|
| Phone layout (top bar, drawer menu, safe areas, 16 px inputs, touch targets) | `src/styles/mobile.css`, `src/App.tsx` |
| Native behaviour (back button, return to app, status bar, keyboard) | `src/web/mobileShell.ts` |
| Secure storage of API keys / vault passphrase (Android Keystore, iOS Keychain) | `src/web/nativeKeys.ts` (`@aparajita/capacitor-secure-storage`) |
| Capacitor config | `capacitor.config.ts` (app id `app.projectgenius.mobile`) |
| Bundle config | `vite.mobile.config.ts` → `npm run build:mobile` |
| Android project / iOS project | `android/`, `ios/` (generated by Capacitor, committed) |

## Your AI keys on the phone

Sign in with your Genius account, open **Settings → Account → Key vault**, type your vault passphrase once and your provider keys are on the phone (tick "do not ask again" and the phone remembers the passphrase in the Keystore/Keychain). Keys are encrypted on the device before they reach your account; see the privacy notes in `docs/DEPLOY-NETLIFY-SUPABASE.md`. Without a vault you can paste a key in the app: it is kept in the Keystore/Keychain of this phone only.

## Build the Android APK

Needs Node 20+, JDK 21 and the Android SDK (platform 36).

```
npm ci
npm run cap:sync                 # builds dist-mobile and copies it into android/ and ios/
cd android
./gradlew assembleDebug          # android/app/build/outputs/apk/debug/app-debug.apk
```

Install on a phone: copy the APK, open it, allow "install unknown apps" for your file manager. Or `adb install -r app-debug.apk`.

### Signed release APK

`./gradlew assembleRelease` signs with a keystore taken from the environment (nothing secret is in the repository):

```
GENIUS_KEYSTORE_FILE=/path/genius.jks  GENIUS_KEYSTORE_PASSWORD=…  GENIUS_KEY_ALIAS=genius  GENIUS_KEY_PASSWORD=…
```

Create your own key once and **keep it safe** (if you lose it you can never update installed apps):

```
keytool -genkeypair -v -keystore genius.jks -alias genius -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 genius.jks   # PowerShell: [Convert]::ToBase64String([IO.File]::ReadAllBytes("genius.jks"))
```

For the GitHub release workflow add four **repository secrets** (Settings → Secrets and variables → Actions): `ANDROID_KEYSTORE_B64` (that base64 text), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. With them the release publishes `Genius_<version>_android.apk` (release-signed). **Without them it publishes `Genius_<version>_android-debug.apk`**: a working, installable APK signed with a throw-away debug key, clearly named as such; Android refuses to update one debug build with another that has a different key, so uninstall the old one first.

## iOS

`ios/App` is a standard Xcode project (Swift Package Manager). On a Mac:

```
npm ci && npm run cap:sync
open ios/App/App.xcodeproj       # choose your team under Signing & Capabilities, then Run / Archive
```

CI (`ci.yml`, job `ios`) compiles the project for the iOS simulator on a macOS runner on every push, **without signing**. Putting the app on a device, TestFlight or the App Store needs an Apple Developer account (99 USD/year), a signing certificate and a provisioning profile, which only you can create; this repository holds none. Until then iOS users can use **Genius Web in Safari** (Share → Add to Home Screen gives an app-like icon).
